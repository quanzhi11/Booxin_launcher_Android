1. 能力边界（先看这个）

能力状态具体表现
主页按时段问候 可用 UI zip 开启 homeGreetingByTime 后，主页标题变为早上好/中午好/晚上好
左右滑动过渡 可用 开启 pageSlideTransitions 后，顶部导航切页与进入/返回游戏使用左右滑动动画
首页 3D 模型 可用 开启 home3dModel 后，首页欢迎区显示当前账号玩家 3D 皮肤（微软拉正版皮肤 / 离线用导入皮肤；逻辑在启动器内）
操控布局 controlLayout 可用 开启 controlLayout 并附带布局 JSON；支持贴图/style、extraLayouts 多面板、outputText、TOGGLE；无 chrome 时默认近透明
JS 命令权限 jsCommands 可用 插件声明 features.jsCommands；启用时需用户授权。页面内可调用白名单 BooxinPlugin.*（toast / openUrl / navigate / close / getInfo）。无 shell、无任意文件、无游戏底层控制
自定义页面 customPages 可用 清单 pages[]（id/title/entry 或 https url；可选 orientation/fullscreen）；启动器 WebView 托管
主页品牌图标 可用 开启 customLauncherIcon 并附带图片后，替换主页左侧品牌圆标（不改系统桌面图标）
自定义界面字体 可用 开启 customFont（或主题包）并附带 .ttf/.otf
完整主题包 customTheme 可用 品牌名、欢迎语、配色、顶栏导航文案、壁纸图/视频；并解锁同包图标与字体
本机插件启用/禁用/卸载/导入 可用 侧边栏「本机插件」；支持商店安装与「导入 zip」；禁用写 .disabled
渲染器/驱动 so 安装 可用 APK 导入或商店下载；解压到本机渲染器目录
换布局 / 自定义页面 XML 未接线 不能替换布局文件或注入任意页面
input / overlay / pack 独立钩子 未接线 可安装到「本机插件」管理，暂无独立运行时行为

UI 插件可深度换肤，但不能改系统桌面图标、系统字体、游戏内 UI，也不能替换布局 XML。 推荐一把梭：features.customTheme: true + theme 对象。

2. 手把手：做一个真正会生效的问候语插件

1在电脑建目录

D:\plugins\my-greeting\
└── booxin-plugin.json

文件名必须恰好是 booxin-plugin.json（全小写，中间是连字符）。

2写入以下内容（可原样复制）

{
  "id": "my-greeting",
  "name": "按时段问候",
  "version": "1.0.0",
  "type": "ui",
  "description": "启用后主页显示早上好/中午好/晚上好。禁用后恢复默认欢迎语。",
  "features": {
    "homeGreetingByTime": true
  }
}

3打 zip（结构必须对）

正确

my-greeting.zip
└── booxin-plugin.json

打开 zip 后第一层就能看见清单。

错误（装不上）

my-greeting.zip
└── my-greeting/
    └── booxin-plugin.json

多套一层文件夹时，请保证清单仍能被搜到；最稳是不要多套。

Windows 资源管理器：进入 my-greeting 文件夹 → 选中 booxin-plugin.json → 右键 →「发送到」→「压缩(zipped)文件夹」→ 改名为 my-greeting.zip。

PowerShell（推荐，结构更稳）：

cd D:\plugins\my-greeting
Compress-Archive -Path .\booxin-plugin.json -DestinationPath ..\my-greeting.zip -Force

也可用官方工具一键打包：文末 附录 · Booxin Studio （前往下载）。 推荐双击 BooxinStudio.exe 用微型 IDE「一键打包」；命令行则用 BooxinStudio-CLI.exe pack 插件目录。

不要用加密 zip、7z、rar、分卷包。客户端只按 zip 解。

4装进启动器后怎么验证

  1. 手机打开 Booxin → 底部「插件」。
  2. 左侧点「本机插件」（商店装完会自动切过来；ADB 推送则手动点）。
  3. 应看到名称「按时段问候」，详情类似：ui · 已启用 · v1.0.0。
  4. 再点底部「主页」。欢迎语应变成：
    • 0:00–10:59 → 早上好
    • 11:00–16:59 → 中午好
    • 17:00–23:59 → 晚上好
  5. 回「本机插件」点「禁用」→ 再回主页 → 应恢复「欢迎使用 Booxin」。

3. UI 插件：清单字段与安装目录（具体）

3.1 安装落盘位置

/data/data/com.booxin.launcher/files/booxin-runtime/ui-plugins/<id>/
├── booxin-plugin.json
├── .ready                 ← 安装成功时写入时间戳
├── .disabled              ← 仅禁用时存在；删除即启用
└── （zip 里其它文件会一并解压到这里）
  • 包名以实际安装为准：正式包一般为 com.booxin.launcher。
  • <id> 来自清单 id；非法字符 \ / : * ? " < > | 会被替换成 _。
  • 相同 id 再安装：先删整个旧目录再写入（覆盖更新）。

3.2 客户端实际读取的字段

「用途」一列写的是用户在启动器里会看到什么变化，不是抽象分类。

JSON 字段要求默认值具体干什么用
id 必需 — 插件唯一 ID，也是本机安装目录名。空 → 安装失败「plugin id 为空」。更新版本时必须保持同一 id。
name 建议 等于 id 「本机插件」列表里显示的标题（用户看到的名字）。
version 建议 1.0.0 列表显示 v1.0.0；商店更新对照用。
type 建议 ui 列表里的类型标签（ui / control / utility…）。真正开不开能力看 features，不看这个字。
description 建议 空 列表标题下方的灰色简介文案。
schema 可选 1 清单格式版本号；目前写 1 即可，方便以后兼容。
minLauncher 可选 空 建议最低启动器版本（展示/自检用），例如 "5.3.6"。
features.homeGreetingByTime 可选 false 主页大标题按时段变成「早上好 / 中午好 / 晚上好」。若主题写了 welcomeMorning 等，优先用主题自定义文案。
features.pageSlideTransitions 可选 false 底部/顶部切页、进入游戏、从游戏返回时，用左右滑动动画代替生硬切换。
features.home3dModel 可选 false 主页欢迎区改为显示当前账号玩家 3D 皮肤（正版皮肤 / 离线导入皮肤），替代纯文字欢迎块。
features.controlLayout 可选 false 进游戏后虚拟按键改用本包布局（见 layoutFile）。多个操控插件同时启用时，只取扫描到的第一个。
layoutFile 操控建议 control_layout.json 主操控面板的 JSON 路径（相对插件目录）。里面写按键位置、键码、贴图、样式。
extraLayouts 可选 [] 额外操控面板。例：战斗 / 建造两套键位。游戏里点悬浮球 → 操控菜单右侧「插件面板」可切换；每个面板单独记住用户拖动位置。
features.customLauncherIcon 可选 false 把主页左侧圆形品牌图标换成插件图片。不改 Android 桌面应用图标。
features.customFont 可选 false 启动器 App 内文字换用插件字体（主页、商店、设置等）。不改系统字体、不改游戏内字体。
features.customTheme 可选 false 打开完整主题：品牌名、配色、导航文案、壁纸等。清单里只要写了 theme 对象也会自动开启。
theme 可选 空对象 主题细节对象，字段见 3.4。
launcherIcon / icon 可选 见候选文件名 品牌图标图片路径，如 icon.png。配合 customLauncherIcon 或主题包使用。
font / fontFile 可选 见候选文件名 字体文件路径，如 fonts/MyFont.ttf（.ttf / .otf / .ttc）。
features.customPages 可选 false 允许插件贡献自定义页面；清单里 pages 非空时也会自动开启。顶栏会出现页面入口。
pages 可选 [] 自定义页面列表，字段见 3.6。可本地 HTML，也可 https 远程页。
features.jsCommands 可选 false 声明页面要用 JS 桥。启用插件时会弹权限；用户同意后，页面里才能调用 BooxinPlugin.*。
根级同名布尔字段 可选 false homeGreetingByTime 等也可写在根级（不放进 features），效果相同。

3.3 清单放置位置

  • 优先：zip 根目录 booxin-plugin.json。
  • 也支持：任意子路径，只要条目名以 booxin-plugin.json 结尾（例如 pkg/booxin-plugin.json）。
  • 若清单在 pkg/ 下，解压时会去掉 pkg/ 前缀，使文件落到安装根目录。

3.5 操控布局：每个字段干什么

开启 features.controlLayout 后，进游戏用本包的虚拟按键。目录示例：

my-control-pack/
├── booxin-plugin.json
├── control_layout.json          ← 主面板
├── control_layout_build.json    ← 可选：extraLayouts
└── assets/
    └── btn.png
{
  "schema": 1,
  "id": "my-control-pack",
  "name": "My Control Pack",
  "version": "1.0.0",
  "type": "control",
  "features": { "controlLayout": true },
  "layoutFile": "control_layout.json",
  "extraLayouts": [
    { "id": "build", "name": "建造", "file": "control_layout_build.json" }
  ]
}

没有 icon、也没有 style/buttonStyle 时，按键默认几乎透明（只留淡描边），容易「装了像没装」。 主题操控包请至少写一套 buttonStyle 或给按钮贴图。

布局文件查找顺序（声明优先）：layoutFile → control_layout.json → layout.json → controls.json → assets/control_layout.json。

布局顶层字段

字段具体干什么用
version布局格式版本，写 4。
buttons虚拟按键数组（跳、潜行、背包、鼠标键等）。
joystick左侧移动轮盘（WASD）。
floatingBall游戏内「控」悬浮球位置；点开操控设置菜单。
gestureQuick手势模式快捷切换按钮位置（综合 / 战斗 / AA）。
buttonStyle / buttonCss本布局所有按键的默认外观；单键 style 可覆盖。

buttons[] 每个字段

字段具体干什么用
id按键稳定 ID。用户拖动后本机用它记住位置；建议写成 jump、lmb 这种固定名，不要每次随机。
label按键上显示的文字（如「跳」「左键」）。用户可在游戏编辑模式「重命名」覆盖。
kind按键行为类型，见下表。决定是点一下、按住、跟手还是开软键盘。
code要模拟的 GLFW 键码或鼠标键。例：空格 32、E 69、左键 0、右键 1。软键盘可写 0。
codes组合键，长度 ≥2。例：[341, 67] = Ctrl+C（修饰键在前）。
outputText / text点按时往游戏输入这段聊天/命令文本（如 /home）。可与 code: 0 做成纯命令键。
x / y按键中心在屏幕上的相对位置，0~1。x=0 最左，x=1 最右；y=0 最上，y=1 最下。例：右下角约 0.90, 0.74。
sizeDp按键边长（密度无关像素），默认约 52，允许 36~160。越大越好按，越小越不挡画面。
icon按钮背景图路径（相对插件目录，如 assets/btn.png）。有图时优先用图，不用 CSS 底。
style / css无贴图时用颜色/圆角/渐变画按钮底；覆盖布局级 buttonStyle。

kind（按下去会发生什么）

kind具体干什么用
KEY_TAP手指抬起时点一次键盘键。适合打开背包 E、聊天 T、丢弃 Q。有 outputText 时改成输入那段文字。
KEY_HOLD按住时键盘键保持按下，松开才放开。适合跳跃（空格）、潜行（Shift）。手指滑出按钮后交给空白区转视角。
MOUSE_HOLD同上，但是鼠标键。适合攻击（左键）、使用/放置（右键）。
KEY_FOLLOW / MOUSE_FOLLOW按住期间按钮跟着手指走并保持按下，松开弹回原位。适合边按边移动手指的战斗键。不会把触摸交给转视角。
KEY_TOGGLE / MOUSE_TOGGLE点一下闩住「按下」，再点一下松开。适合需要长时间按住又不想一直按着的场景。
SOFT_KEYBOARD切换 Android 系统软键盘（打字聊天）。布局里没写时，启动器会自动补一个。
SCROLL模拟鼠标滚轮切物品栏。code ≥ 0 向上，负数向下。

FCL 兼容特殊码（单码）：-1 左键、-2 Ctrl+C、-3 右键、-4 ←、-5 →。

joystick / floatingBall / gestureQuick

字段具体干什么用
joystick.x / y移动轮盘中心位置（0~1）。常见左下角约 0.13, 0.84。
joystick.sizeDp轮盘直径，约 120~220，默认约 150。
joystick.follow默认 false。为 true 时：按下轮盘会跳到指下；拖出外圈时底盘追手；松开回弹。适合动态摇杆手感。
floatingBall.x / y「控」悬浮球位置。点它打开陀螺仪 / 联机 / 自定义布局 / 退出等菜单。
gestureQuick.x / y手势模式快捷钮位置。用来在「综合 / 战斗 / AA」触摸手势模式间切换。

用户在游戏里拖动按键/轮盘/重命名后，位置与文案写入本机，并与插件贴图样式合并：插件管外观，本机管几何与自定义名字。

style / css / buttonStyle（按钮长什么样）

字段别名具体干什么用
backgroundColorbackground / bg按钮填充色。也可用 transparent 做成空心键。
borderColorborder-color描边颜色（圆圈边缘）。
borderWidthborder-width描边粗细（dp）。
borderRadiusradius圆角大小。写 50% / full / circle → 正圆。
shape—外形：oval/circle 圆；rect 方；roundrect/pill 圆角矩形。
gradient—渐变填充，至少 2 个颜色。也可用 "linear-gradient(#a,#b)" 字符串。
gradientOrientation—渐变方向：tl_br（左上→右下）、top_bottom、left_right 等。
textColorcolor按钮上 label 文字颜色。
opacityalpha整颗按钮透明度 0.15~1。越小越透、越不挡游戏画面。
pressScalepress-scale按下时缩小比例 0.72~1，默认约 0.90，用来做按压缩放反馈。
pressEffect或 "jelly": truesquash：按下瞬间缩小；jelly：压扁再弹回，手感更「果冻」。

绘制优先级：icon 贴图 → style/css → 启动器默认近透明圆形底。

icon 规则：相对插件目录；仅 png/webp/jpg/jpeg；禁止绝对路径和 ..。

3.6 自定义页面 / JS 桥：每个字段干什么

页面跑在启动器 WebView 里（启动器 UI 层），不是游戏 JVM/SDL 底层。适合做说明页、工具页、论坛壳。

{
  "id": "booxin.sample.pages",
  "name": "示例·自定义页面",
  "version": "1.0.0",
  "type": "ui",
  "features": {
    "customPages": true,
    "jsCommands": true
  },
  "pages": [
    {
      "id": "demo",
      "title": "示例页",
      "entry": "pages/index.html"
    },
    {
      "id": "forum",
      "title": "论坛",
      "url": "https://example.com/forum",
      "orientation": "portrait",
      "fullscreen": true
    }
  ]
}

pages[] 字段

字段具体干什么用
id页面内部 ID，同一插件内唯一，用于打开/切换页面。
title顶栏/入口上显示的标题，用户看得见。
entry / html / file插件包内的本地 HTML 路径，如 pages/index.html。和 url 二选一（有 url 优先远程）。
url / href / remote直接打开的 https 网址（论坛、文档站）。非 https 会被忽略。
orientation打开该页时锁定方向：portrait（竖屏）/ landscape（横屏）；也认「竖屏」「横屏」。
fullscreen / immersivetrue 时沉浸式打开，隐藏部分页面铬，内容区更大。

BooxinPlugin（需用户授权 jsCommands）

方法具体干什么用
getInfo()读取启动器/插件基础信息（给页面展示用）。
toast(msg)弹出一条短提示（Android Toast）。
openUrl(https)用系统浏览器打开链接（仅 http/https）。
navigate(目标)跳到启动器内页：home / versions / community / multiplayer / ai / pluginstore / plugins / settings。
close()关闭当前插件页面，回到启动器。

没有：shell、读写任意文件、NativeJvm、SDL、往游戏注入按键。不要指望用页面插件改游戏底层。

4. 问候语 / 图标 / 字体：具体判定规则

4.1 问候语

代码在进入/回到主页时执行（onResume）。判定顺序：

  1. 扫描 ui-plugins/*/ 下所有已安装插件。
  2. 跳过带 .disabled 的目录。
  3. 读取各自清单；任一启用插件的 homeGreetingByTime == true 即生效。
  4. 取手机本地时区的小时 HOUR_OF_DAY（0–23）：
小时显示文案例子
hour < 11早上好07:30 → 早上好
11 ≤ hour < 17中午好12:00 → 中午好
hour ≥ 17晚上好20:15 → 晚上好
  • 未启用任何问候语插件时：固定显示「欢迎使用 Booxin」。
  • 装了但点了「禁用」：等同未启用。
  • 多个插件都开了该 feature：只要有一个启用即可（并集）。

4.2 customLauncherIcon（主页品牌图标）

只替换主页左侧品牌圆标，不会改 Android 桌面上的应用图标。

  1. 启用插件且 customLauncherIcon == true。
  2. 按名称排序后取第一个找到有效图片的插件。
  3. 图片路径优先用清单 launcherIcon（或 icon）；未写则依次尝试： icon.png / icon.webp / icon.jpg / icon.jpeg / launcher-icon.png / assets/icon.png。
  4. 找不到可用图 → 回退默认 ic_launcher_round。
{
  "id": "my-brand-icon",
  "name": "自定义主页图标",
  "version": "1.0.0",
  "type": "ui",
  "launcherIcon": "icon.png",
  "features": {
    "customLauncherIcon": true
  }
}

4.3 customFont（界面字体）

只替换启动器 App 内文字（主页、商店、设置、聊天等），不改 Android 系统字体，也不改游戏内字体。 等宽日志区域会保留 monospace。

  1. 启用插件且 customFont == true。
  2. 按名称排序后取第一个找到有效字体文件的插件。
  3. 路径优先用清单 font（或 fontFile）；未写则依次尝试： font.ttf / font.otf / fonts/font.ttf / fonts/font.otf / assets/font.ttf / assets/font.otf。
  4. 支持扩展名：.ttf、.otf、.ttc。请确认字体许可允许分发。
  5. 启用/禁用/卸载后会立即重刷当前界面；若个别页面未变，切页或回前台即可。
{
  "id": "my-ui-font",
  "name": "自定义界面字体",
  "version": "1.0.0",
  "type": "ui",
  "font": "fonts/MyFont.ttf",
  "features": {
    "customFont": true
  }
}

4.4 customTheme（完整主题包，权限最大）

开 customTheme（或清单里写了 theme 对象）后，同一包还可直接带上 图标 / 字体文件，无需再单独开 customLauncherIcon / customFont。

每个 theme 字段改界面哪里、配色/导航分别管什么，见上方 3.4 主题字段说明（表格比这里更全）。

  • 文案类：brandName、welcome*、homeLaunchText 等 → 主页看得见的字
  • 视觉类：colors.*、backgroundImage/backgroundVideo、hideOrbs → 颜色与壁纸
  • 导航类：nav.* → 底栏/顶栏各页名字

插件不能运行任意代码；只能改启动器已接线的这些字段。想加新能力需要发版启动器。 多个主题包同时启用时，按插件名称排序取第一个。

5. 本地自测（不上架）

5.1 ADB 推送 UI 插件

电脑已装 platform-tools，手机开 USB 调试，启动器包名为 com.booxin.launcher：

# 在电脑当前目录放好 booxin-plugin.json

adb shell mkdir -p /data/data/com.booxin.launcher/files/booxin-runtime/ui-plugins/my-greeting

# 无 root 时优先用 run-as（debug 包通常可用；release 可能受限）
adb shell run-as com.booxin.launcher mkdir -p files/booxin-runtime/ui-plugins/my-greeting

adb push booxin-plugin.json /sdcard/booxin-plugin.json
adb shell run-as com.booxin.launcher cp /sdcard/booxin-plugin.json \
  files/booxin-runtime/ui-plugins/my-greeting/booxin-plugin.json

adb shell run-as com.booxin.launcher sh -c \
  "echo $(date +%s) > files/booxin-runtime/ui-plugins/my-greeting/.ready"

然后：打开启动器 → 插件 → 本机插件 → 点「刷新」→ 回主页看文案。

  "echo 1 > files/booxin-runtime/ui-plugins/my-greeting/.disabled"

测卸载：

adb shell run-as com.booxin.launcher rm -rf \
  files/booxin-runtime/ui-plugins/my-greeting

5.2 渲染器本地导入

  1. 启动器 → 插件 → 左侧「本机渲染器」。
  2. 点「导入 APK」。
  3. 选你的 .apk。
  4. 成功后列表出现名称、版本、类型「渲染器」、状态「已安装/已启用」。

6. 渲染器 / 驱动：具体打包要求

6.1 APK 内部结构（按这个做）

my-renderer.apk
├── plugin.json                 ← 推荐（也认 assets/plugin.json）
├── AndroidManifest.xml
└── lib/
    ├── arm64-v8a/              ← 真机主流，强烈建议有
    │   ├── libmygl.so          ← 文件名 = glLib
    │   └── （其它依赖 .so）
    └── armeabi-v7a/            ← 可选
        └── libmygl.so

6.2 plugin.json 读写位置

客户端按顺序找：

  1. assets/plugin.json
  2. plugin.json（APK 根）

都没有时，会按 so 文件名猜（含 gl4es / ltw / angle / OSMesa / mobileglues 等），不稳定，别靠猜。

6.3 推荐完整清单

{
  "id": "my-gl-renderer",
  "name": "My GL Renderer",
  "version": "1.0.0",
  "type": "RENDERER",
  "glLib": "libmygl.so",
  "eglLib": "libEGL.so",
  "rendererToken": "opengles3",
  "libGlEs": "3",
  "kindName": null,
  "disguiseAsGl4es": false,
  "extraEnv": {
    "LIBGL_ES": "3"
  }
}
字段要求具体含义
id 必需 安装目录名：…/booxin-runtime/plugins/<id>/（并可能镜像到 renderers/<id>/）
glLib 必需 主库文件名。解压后目录里必须有这个文件，否则报「插件缺少 xxx」
type 建议 清单枚举用 RENDERER / DRIVER；商店申请填小写 renderer / driver
eglLib 可选 配套 EGL 库文件名，默认 libEGL.so。启动器加载 GL 时一并找它。
rendererToken 可选 告诉启动链路「这是哪种后端」，默认 opengles3。例：vulkan_zink。影响识别与展示，不是随意字符串装饰。
libGlEs 可选 GLES 主版本号字符串，默认 "3"。会作为环境/启动参数传给游戏进程。
extraEnv 可选 启动游戏时额外注入的环境变量。例：{"LIBGL_ES":"3"}。用来调渲染器行为。
disguiseAsGl4es 可选 默认 false。部分老模组/启动路径只认 gl4es；开了会伪装成 gl4es 环境（仅 gl4es 类方案需要）。
kindName 可选 渲染器种类显示名；不写则按 type / token 推断。

6.4 ABI 提取顺序（客户端行为）

  1. 先按设备 Build.SUPPORTED_ABIS 顺序找 lib/<abi>/*.so。
  2. 某个 ABI 解出至少一个 so 就停，不再解其它 ABI。
  3. 只解一层文件名（不要 lib/arm64-v8a/subdir/a.so）。
  4. 解压后检查是否存在 glLib；没有则尝试在已解压 so 里找近似名并复制改名。

6.5 可选 Manifest 元数据

<meta-data android:name="booxin.plugin" android:value="renderer" />
<meta-data android:name="org.lwjgl.opengl.libname" android:value="libmygl.so" />

用于扫描「本机已安装的第三方渲染器插件 APK」。普通导入本地 APK 主要仍看 plugin.json + so。

7. 商店点「下载安装」时，客户端具体怎么走

下载始终在启动器内部完成（不跳系统浏览器），并自动跟随 HTTP 重定向（短链 / CDN 跳转可用）。

  1. 读上架记录的 downloadUrl（空则提示缺少下载链接）。
  2. 在 App 内下载文件（支持重定向；最终 URL / Content-Disposition / Content-Type 会参与判断）。
  3. 再判定包类型并安装：
    • renderer / driver → 按 APK 装进「本机渲染器」
    • URL/响应头像 .apk，或包内有 AndroidManifest.xml / classes.dex → APK
    • 包内有 booxin-plugin.json，或类型为 UI 类 / 其它未知 → 按 UI zip 装进「本机插件」
商店 typeURL 建议结果
ui https://…/xxx.zip、短链重定向到 zip、或启动器上传 App 内下载 →「本机插件」
renderer https://…/xxx.apk 或重定向到 apk App 内下载 →「本机渲染器」
任意 网盘「分享页」HTML（不是文件直链/跳转） 会下到网页内容导致安装失败；请用真正的文件下载链

短链可以，但最终必须落到可下载的 zip/apk 文件。UI 包务必含 booxin-plugin.json； 渲染器用 renderer/driver。

8. 申请上架：逐步点哪里、填什么

  1. 启动器登录联机账号（未登录不能提交）。
  2. 底部导航点「插件」。
  3. 左侧点「申请上架」（或底部申请按钮，以你版本文案为准）。
  4. 第 1 步填：
    • 插件名称：商店显示名，例如「按时段问候」。
    • 类型 / 分区：UI 选「UI 插件」；渲染器选「渲染器」。
    • 简介：写清用途 + 使用步骤 + 能力边界。
  5. 第 2 步：上传文件（≤250MB）或填 HTTPS 外链（可只填一种）。
  6. 提交成功提示「申请已提交，请等待审核」。
  7. 在「我的申请」可看状态：审核中 / 已通过 / 未通过（未通过有原因）。

简介可直接套用

【功能】启用后，主页欢迎语按本地时间显示早上好/中午好/晚上好。
【安装】商店下载安装 → 左侧「本机插件」保持「已启用」→ 回到主页查看。
【关闭】本机插件 → 禁用 或 卸载。
【说明】本插件不会修改主题色；当前版本支持问候语 / 主页品牌图标 / 界面字体。
【包格式】zip，内含 booxin-plugin.json，id=my-greeting。

10. 常见报错 / 现象对照

你看到的常见原因怎么改
缺少 booxin-plugin.json zip 结构错、文件名大小写错、双重压缩 按第 2 节重打包，打开 zip 确认第一层有清单
plugin id 为空 清单没写 id 或写成空 补上非空 id
无效的插件包 文件长度为 0 / 不是有效 zip 重新压缩，别传空文件
插件缺少 libxxx.so APK 无对应 ABI，或 glLib 文件名不一致 补 arm64-v8a，并对齐 glLib
装上了主页仍是「欢迎使用 Booxin」 未开 feature、已禁用、没回到主页 检查 features、启用状态、切换一次主页
开了 customLauncherIcon 图标不变 缺图 / 路径写错 / 被别的插件抢先 / 未回主页 确认 zip 内有图；禁用其它图标插件；切回主页
开了 customFont 字体不变 缺字体文件 / 扩展名不对 / 被禁用 / 损坏的 ttf 确认包内有 .ttf/.otf；用 Studio validate；切页重进
桌面应用图标没变 预期行为 该 feature 只改主页内品牌标，不改系统桌面图标
下载失败 / 安装失败 链接最终不是 zip/apk（HTML 分享页）、或包结构不对 用可跟随重定向的文件下载链；确认包内清单；见第 7 节
UI 安装失败但进度走完 下到的是 HTML 分享页 换真正文件链，或 ≤250MB 用启动器上传

11. 发布前逐条勾

  • UI：zip 内能直接看到 booxin-plugin.json，id 非空
  • 问候语：真机验证 启用→主页文案变 / 禁用→恢复默认
  • 图标：真机验证 启用→主页左侧圆标变 / 禁用→恢复默认
  • 字体：真机验证 启用→界面文字变 / 禁用→恢复默认；确认许可可分发
  • 主题包：品牌名、配色、导航/主页按钮文案、壁纸图或视频、hideOrbs 至少验证一项可见变化
  • 操控包：提供 icon 或 buttonStyle（否则默认近透明难辨认）；进游戏验证布局；有 extraLayouts 时验证面板切换
  • 自定义页面：本地 entry 或 https url；fullscreen/orientation 按需验证
  • 渲染器：arm64-v8a 下存在与 glLib 同名的 so；可用「导入 APK」装上
  • 商店 type 与包格式一致；下载链最终能落到 .zip / .apk（可用短链重定向）
  • 简介写了「会做什么 / 不会做什么」，不夸大未接线能力
  • 更新版本时保持同一 id，只改 version
  • 无恶意行为；资源与库许可合规
